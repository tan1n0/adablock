# JSSA 与 Full / S / B 比较

独立运行目录：`/root/adablock_jssa_20261023_01`。旧结果、旧环境和冻结权重不修改。

## 本轮比较

- 使用上一轮自主预算评测的原始 450 道题：单值检索、多值检索、变量追踪，各 8K / 16K / 32K，每组 50 题。直接复用输入 token IDs，不重新抽样或重新套模板。
- Full / S / B 使用同一个 Llama-3.1-8B-Instruct、BF16、完整注意力预填充、贪心解码、EOS 和共同的 128 token 输出上限。该上限沿用已有实验，不声称它是所有 RULER 任务各自的官方默认值。
- S / B 保留自主预算：90% 注意力覆盖训练目标，部署分位点 0.95，原有 sink/local 和快速 Gram 摘要。
- JSSA：rank 32；每 KV 头读取 512 / 1024 / 2048 / 4096 个 token，2048 为官方默认预算。没有额外强制加入 S/B 的 sink/local。
- 先完成校准和内核测试，再进行最长输入的 Full/all-read 检查，以及每任务每长度一道题的小样本。小样本正常完成后启动 450 题。

## 指标口径

1. 质量：原官方 RULER 评分器，保存答案、原始生成 token 和截断标志。
2. 实际读取量：每个解码步、每层、每 KV 头的选中 token 累加；S/B 包含 sink/local/current，并另外报告补齐后的计算量。该数值是逻辑选中量，不等同于硬件内存事务计数。
3. JSSA 额外扫描：全部历史 rank32 投影键的逻辑字节数单列，不能把只读 B 个原始 KV token 理解为其全部内存开销。
4. 解码耗时：GPU 同步、预热后测量，预填充和索引构建单列；每张 GPU 一个评测进程。除了自然回答耗时，小样本还固定解码 16 步、重复 3 次，比较每 token 时间。
5. JSSA 索引构建为避免 24GB 显存同时保留两份前缀，采用 CPU 暂存再建立分页缓存。其构建耗时含适配的传输成本，**不能视为原生 JSSA 的端到端耗时**；纯解码计时不包含该暂存。
